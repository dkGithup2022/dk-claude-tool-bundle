# tool-workflow-planner-extract-plan (초안)

## 0. 배경

워크플로 요청을 만들 수 있는 계획서로 바꾸는 스킬이다. `tool-workflow-planner` 가 요청만으로 계획서를 채울 수 없을 때 부른다.
여기서 정한 계획서 형식(2 절)과 추론 규칙(3 절)은 `tool-workflow-planner` 도 쓴다.
단계 제작 스킬(`tool-add-*-task`)은 계획서의 단계별 상세만 보고 코드를 만들기 때문에, 2 절의 필수 항목이 하나라도 빠지면 만들 수 없다.

## 1. 입력과 산출물

- **입력**: 계획서 경로. `## 요청` 이 있고, 흐름도와 단계별 상세는 비었거나 일부만 있다.
- **산출물**: 같은 계획서. 흐름도가 `확답`, 모든 단계가 `확답`, `## 확인 결과` 가 채워진 상태. 계획서 전체의 확답은 `tool-workflow-planner` 가 받는다.
- 코드는 쓰지 않는다.

## 2. 계획서 스펙

### 2.1 모양

```markdown
# 워크플로: <이름>

## 요청
{사용자가 말한 그대로}

## 흐름도                                  상태: 확답 전
{2.2 표기}

## 단계별 상세                             상태: 0 / {단계 수} 확답
### <노드 경로>
- 종류: <수행 종류>
- 결과 종류: <DATA / FILES>
- 입력: <2.3 의 값>
- 출력: <2.3 의 값>
- 상세: <2.4 의 항목>
- 다시 수행: <안전 / 쓰기를 별도 단계로 / 해당 없음>
- 상태: 확답 전

## 같이 쓰는 코드
- <위치>: <무엇>. 쓰는 단계: <노드 경로들>          (없으면 "없음")

## 확인 결과
{4 절 5 의 목록과 결과}

## 계획서 확답                             상태: 확답 전

## 진행 기록
```

### 2.2 흐름도

| 줄 | 쓸 수 있는 값 |
|---|---|
| 맨 위 줄 | 워크플로 이름. 자식은 차례대로 실행 |
| 자식이 있는 줄 (묶음) | `[IN_ORDER]`, `[FOR_EACH_ITEM: <노드 이름>.<필드>]` |
| 자식이 없는 줄 (단계) | `[CODE]`, `[CLAUDE_P]`, `[MAIN_SESSION_SHOW]`, `[MAIN_SESSION_ASK]`, `[MAIN_SESSION_TALK]`, `[SUBAGENT]` |
| 어느 줄에나 (선택) | `[run_if: answer_is(<노드 이름>, "<값>")]` |

- 받지 않는 것: 앞 단계로 되돌아가기, 동시 실행, `answer_is` 가 아닌 조건, 앞 결과를 계산해서 만든 반복 항목. 요청에 있으면 위 값으로 바꾼 안을 제안한다 (5.4).
- 이름: 영문 소문자·숫자·`_`. 워크플로 안에서 겹치지 않는다. 순서 번호를 붙이지 않는다.
- 노드 이름은 앞 결과를 가리킬 때 쓰고, 노드 경로(맨 위 이름을 뺀 `묶음/단계`)는 폴더 위치와 `### <노드 경로>` 제목에 쓴다.

### 2.3 단계별 상세: 공통 항목

| 항목 | 필수 | 올 수 있는 값 | 코드에서 |
|---|---|---|---|
| 종류 | 예 | 흐름도의 수행 종류와 같음 | `PerformedBy`, `request_type` |
| 결과 종류 | 예 | `DATA` (dict), `FILES` (텍스트 파일 md·txt·코드) | `output_kind` |
| 입력 | 예 | `없음`, `← <노드 이름>.<필드>`, `← <노드 이름>.<필드> (항목 전부)`, `← <노드 이름> (파일)`, `← 지금 항목`. 여럿이면 줄마다 하나 | `reads`, `context.read(...)`, `context.current_item()` |
| 출력 | 예 | DATA: `→ { <필드>: <타입>, ... }` 또는 `없음`. FILES: `→ 파일: <파일 이름> (<형식>)` | `TaskOutput(...)` |
| 상세 | 예 | 2.4 | 종류별 |
| 다시 수행 | CODE 가 포트에 쓸 때 | `안전`, `쓰기를 별도 단계로`, `해당 없음` | |
| 상태 | 예 | `확답 전`, `확답` | |

- 타입: `str`, `int`, `float`, `bool`, `list[<타입>]`, `<타입> | None`.
- 묻지 않고 정해지는 것: Task 키 `<워크플로>.<노드 이름>`, 파일 `<노드 경로>/<노드 이름>_task.py`.

### 2.4 단계별 상세: 종류별 상세

| 종류 | 필수 항목 |
|---|---|
| `CODE` | 하는 일 (한두 문장), 쓸 model·port (`없음` / 있는 것의 이름 / `새로 필요: <무엇>`) |
| `CLAUDE_P` | 프롬프트 본문 전체, 출력 필드마다 이름·타입·한 줄 설명 (FILES 면 `files: list[PromptFile]` 과 만들 파일), 입력 글 예시 한 줄 |
| `MAIN_SESSION_SHOW` | 보일 글. 앞 결과를 넣을 자리는 `{<노드 이름>.<필드>}` |
| `MAIN_SESSION_ASK` | 질문, 선택지, 선택지 밖의 답을 받을지 |
| `MAIN_SESSION_TALK` | 대화 목표, 첫 말 |
| `SUBAGENT` | 에이전트 이름, 지시문 전체(작업, 방법, 끝내기 전 확인, 결과 형식과 예시), 도구, 모델, 파일이 없으면 실패로 볼지 |

## 3. 추론 규칙

사용자가 말하지 않은 항목은 아래 규칙으로 채우고, 값 뒤에 `(추론)` 을 붙여 보인다. 사용자가 말한 값은 바꾸지 않는다.

### 3.1 수행 종류

| 하려는 일 | 종류 |
|---|---|
| 사용자에게 글을 보임 | `MAIN_SESSION_SHOW` |
| 사용자에게 정해진 선택지로 물음 | `MAIN_SESSION_ASK` |
| 사용자와 자유롭게 이야기함 | `MAIN_SESSION_TALK` |
| 정해진 계산, 저장된 데이터·API 읽고 쓰기 | `CODE` |
| 입력 글만 보고 판단하거나 글을 만듦 (도구 불필요) | `CLAUDE_P` |
| 도구가 필요한 작업 (파일 읽기·찾기, 여러 번 고쳐 쓰기) | `SUBAGENT` |
| "메인 세션이 이 프롬프트로 작업한다" | 메인 세션은 사용자와 주고받기만 한다. 도구가 필요 없으면 `CLAUDE_P`, 필요하면 `SUBAGENT` |

### 3.2 항목별

| 항목 | 규칙 |
|---|---|
| 단계 이름 | 하는 일을 영문 `동사_목적어` 로 (`make_joke`, `collect_fruits`) |
| 묶음 | 반복하거나 여러 단계에 같은 조건을 걸 때만 만든다. 그 밖의 단계는 맨 위 줄 바로 아래 |
| 묶음 이름 | 반복이면 `<하는 일>_each` (`confirm_each`), 아니면 묶은 일의 이름 (`check`) |
| 반복 항목 이름 | 항목을 복수 명사로 (`fruits`). `<노드 이름>.<필드>` 의 필드는 `list` 여야 함 |
| 결과 종류 | SHOW·ASK·TALK → DATA. SUBAGENT → FILES. CODE·CLAUDE_P → 결과를 사람이 읽거나 뒤 단계가 글째로 넘기면 FILES, 뒤 단계가 값으로 쓰면(조건, 반복, 계산) DATA |
| 입력 | 하는 일에 나오는 앞 결과. 반복 안이면 `← 지금 항목`. 반복 밖에서 반복 안을 읽으면 `(항목 전부)` |
| 출력 | ASK `→ { answer: str }`, TALK `→ { from: str, to: str, transcript: str \| None }`, SHOW `없음`, SUBAGENT `→ 파일: <이름>.md (<형식>)`. CODE·CLAUDE_P 의 DATA 는 뒤 단계가 읽는 필드만 |
| 조건 | 요청에 "~면", "~할지 묻고"가 있을 때만 `answer_is`. 조건이 될 질문 단계가 없으면 ASK 단계를 앞에 더한다 |
| 다시 수행 | CODE 가 포트에 쓰고 같은 값을 두 번 써도 결과가 같으면 `안전`, 아니면 사용자에게 묻는다 |
| 같이 쓰는 코드 | 같은 묶음의 두 단계 이상이 같은 규칙(예: 선택지 밖의 답 거절)을 쓰면 부모 클래스 하나를 그 묶음 폴더에 둔다 |

### 3.3 종류별 상세의 초안

| 종류 | 사용자가 주지 않았을 때 |
|---|---|
| `CODE` | 하는 일을 요청 문장에서 한두 문장으로. `src/{pkg}/model/`, `src/{pkg}/port/` 에서 쓸 것을 찾아 제안, 없으면 `새로 필요: <무엇>` |
| `CLAUDE_P` | 입력이 무엇인지, 할 일, 출력 필드마다 무엇을 넣는지를 쓴 본문 초안. 입력 글 예시는 입력 노드의 값으로 한 줄 |
| `MAIN_SESSION_SHOW` / `ASK` / `TALK` | 요청 문장에서 글·질문·선택지·목표·첫 말을 만든다. 선택지 밖의 답은 받지 않음 |
| `SUBAGENT` | 에이전트 이름은 `<하는 일>-<결과>` (`joke-note-writer`). 지시문은 작업, 방법, 끝내기 전 확인, 결과 형식과 예시로 초안. 도구는 `Write` 와 꼭 필요한 것만, 모델 `sonnet`, 파일이 없어도 실패로 보지 않음 |

## 4. 대화 순서

한 번에 한 가지만 묻는다. 확답을 받을 때마다 계획서에 바로 적는다.

1. **요청 확인**: `## 요청` 을 읽는다. 흐름도를 그릴 수 없으면 아래를 하나씩 묻는다.
   - 무엇을 차례대로 하는가
   - 사용자에게 무엇을 보이거나 묻는가
   - 어디서 반복하거나 건너뛰는가
2. **흐름도**: 3 절로 흐름도를 만들어 2.2 표기로 보인다. 이름, 순서, 종류, 반복, 조건만 확인한다. 고치면 다시 보인다. 확답이면 `## 흐름도` 를 `확답` 으로.
3. **단계별 상세**: 흐름도 위에서 아래로, 한 번에 한 단계.
   - 3 절로 채운 상세를 보이고 맞는지, 고칠 곳이 있는지 묻는다.
   - `CLAUDE_P` 본문과 `SUBAGENT` 지시문은 전체를 보인다. 요약으로 확답받지 않는다.
   - 새 model·port 가 필요하면 `새로 필요: <무엇>` 으로 적고 넘어간다. 만드는 것은 `tool-workflow-planner` 가 나중에 한다.
   - 확답이면 그 단계의 `상태` 와 절의 `n / 전체 확답` 을 고친다.
4. **같이 쓰는 코드**: 3.2 의 규칙에 해당하면 위치와 쓰는 단계를 보이고 확답받는다.
5. **확인**: 아래를 확인해 `## 확인 결과` 에 적는다. 어긋나면 사용자에게 보이고 그 단계로 돌아간다.
   1. 모든 `← <노드 이름>.<필드>` 의 노드가 있고, 그 노드의 출력에 그 필드가 있고, 타입이 맞는다. `← <노드 이름> (파일)` 의 노드는 결과 종류가 FILES 다.
   2. 입력이 가리키는 노드가 흐름도에서 이 단계보다 앞이다.
   3. `FOR_EACH_ITEM: <노드 이름>.<필드>` 의 필드 타입이 `list[...]` 다.
   4. `answer_is(<노드 이름>, "<값>")` 의 노드가 `MAIN_SESSION_ASK` 이고, 값이 그 선택지 중 하나이고, 조건이 붙은 줄보다 앞이다.
   5. 입력이 `run_if` 가 붙은 줄(또는 그 아래)의 출력을 가리키면, 읽는 단계에 같은 조건을 붙였거나 결과가 없을 때 쓸 값을 상세에 적었다.
   6. 포트에 쓰는 `CODE` 단계는 `다시 수행` 이 정해졌다.
   7. 반복 밖 단계가 반복 안 단계의 출력을 읽으면 입력에 `(항목 전부)` 가 붙었다.
6. **돌려주기**: `tool-workflow-planner` 로 돌아간다.

## 5. 케이스별 예시

### 5.1 보이기·묻기·조건·반복

요청: "글을 보여 주고, 대화로 좋아하는 과일을 묻고, 그 결과를 확인할지 묻고, 확인한다면 하나씩 다시 묻는다."

```
demo
├─ hello              [MAIN_SESSION_SHOW]
├─ talk               [IN_ORDER]
│  ├─ listen          [MAIN_SESSION_TALK]
│  └─ collect_fruits  [CODE]
├─ check              [IN_ORDER]
│  ├─ ask_check       [MAIN_SESSION_ASK]
│  └─ confirm_each    [FOR_EACH_ITEM: collect_fruits.items]  [run_if: answer_is(ask_check, "예")]
│     └─ confirm      [MAIN_SESSION_ASK]
└─ bye                [MAIN_SESSION_SHOW]
```

```markdown
### check/ask_check
- 종류: MAIN_SESSION_ASK
- 결과 종류: DATA (추론)
- 입력: 없음
- 출력: → { answer: str } (추론)
- 상세: 질문 "과일마다 확인할까요?", 선택지 "예" / "아니요", 선택지 밖의 답은 받지 않음 (추론)
- 다시 수행: 해당 없음
- 상태: 확답

### check/confirm_each/confirm
- 종류: MAIN_SESSION_ASK
- 결과 종류: DATA (추론)
- 입력: ← 지금 항목
- 출력: → { answer: str } (추론)
- 상세: 질문 "{지금 항목} 맞나요?", 선택지 "맞음" / "아님", 선택지 밖의 답은 받지 않음 (추론)
- 다시 수행: 해당 없음
- 상태: 확답

## 같이 쓰는 코드
- check/choose_task.py: 선택지 밖의 답을 거절하는 부모 클래스. 쓰는 단계: check/ask_check, check/confirm_each/confirm
```

### 5.2 코드 → 프롬프트 → 서브에이전트 → 보이기

요청: "카운터를 1 올리고, 그 숫자로 말장난을 만들고, 해설 메모를 파일로 쓰게 하고, 둘 다 보여 준다."

```
count_joke
├─ count_up     [CODE]
├─ make_joke    [CLAUDE_P]
├─ write_note   [SUBAGENT]
└─ show_joke    [MAIN_SESSION_SHOW]
```

```markdown
### make_joke
- 종류: CLAUDE_P
- 결과 종류: DATA (추론: show_joke 가 joke 필드를 씀)
- 입력: ← count_up.count
- 출력: → { joke: str }
- 상세:
  - 프롬프트 본문: "입력으로 숫자 하나가 주어진다. 그 숫자의 발음이나 모양을 이용한 한국어 말장난을 한 문장으로 만든다. joke 필드에 그 문장만 넣는다."
  - 출력 필드: joke: str — 숫자를 이용한 말장난 한 문장
  - 입력 글 예시: "숫자: 8"
- 다시 수행: 해당 없음
- 상태: 확답

### write_note
- 종류: SUBAGENT
- 결과 종류: FILES (추론)
- 입력: ← count_up.count, ← make_joke.joke
- 출력: → 파일: note.md (마크다운 해설 메모)
- 상세: 에이전트 joke-note-writer, 지시문(전체), 도구 Write, 모델 haiku, 파일이 없어도 실패로 보지 않음
- 다시 수행: 해당 없음
- 상태: 확답
```

### 5.3 claude -p 가 파일 여러 개를 남김

요청: "회의 내용을 대화로 듣고, 결정 사항과 할 일을 각각 md 문서로 정리해서 보여 준다."

```
meeting_notes
├─ listen_meeting   [MAIN_SESSION_TALK]
├─ write_notes      [CLAUDE_P]
└─ show_notes       [MAIN_SESSION_SHOW]
```

```markdown
### write_notes
- 종류: CLAUDE_P (추론: 대화 글만 보고 문서를 만듦, 도구 불필요)
- 결과 종류: FILES (추론: 사람이 읽는 문서)
- 입력: ← listen_meeting.transcript, ← listen_meeting.from, ← listen_meeting.to
- 출력: → 파일: decisions.md (결정 사항 목록), todos.md (할 일 목록)
- 상세:
  - 프롬프트 본문: (초안 전체)
  - 출력 필드: files: list[PromptFile] — decisions.md, todos.md 두 파일
  - 입력 글 예시: "user: 다음 주 금요일까지 시안을 내기로 했어요"
- 다시 수행: 해당 없음
- 상태: 확답 전
```

### 5.4 그대로 표현할 수 없는 요청

요청: "초안을 만들고, 마음에 안 들면 다시 만들게 해 줘."

- 앞 단계로 되돌아가기는 없다 (2.2).
- 제안: 초안을 만든 뒤 "다시 만들까요?"를 묻고(`ASK`), "예"면 고쳐 만드는 단계를 한 번 더 둔다(`run_if: answer_is(ask_redo, "예")`). 그 뒤로도 고치고 싶으면 워크플로를 다시 실행한다.

```
draft
├─ write_draft    [CLAUDE_P]
├─ show_draft     [MAIN_SESSION_SHOW]
├─ ask_redo       [MAIN_SESSION_ASK]
└─ rewrite_draft  [CLAUDE_P]  [run_if: answer_is(ask_redo, "예")]
```
